# Access 架构与网络部署参考（C/S、B/S 与网络操作模式）

> 整合自 Access 软件网三篇只读参考：《C/S 结构与 B/S 结构简述》《为什么说 B/S 结构优于 C/S》《Access 的网络操作模式简介》。
> 本文帮你在「阶段 0 选底座」「阶段 1 需求设计」「阶段 8 部署与运维」做架构取舍。它不是索引表，遇到架构/部署疑问时读对应一节。

## 一、C/S 与 B/S 是什么

- **C/S（Client/Server，客户机/服务器）**：任务分配到客户端与服务端，充分利用两端硬件；传统两层结构，需为不同操作系统开发不同版本，难适应百台以上局域网并发，代价高、效率低。
- **B/S（Browser/Server，浏览器/服务器）**：用户界面用 WWW 浏览器实现，主要事务逻辑在服务器端（三层结构）。客户端极"瘦"，维护/升级只动服务器，总体拥有成本（TCO）低；不同地点、不同接入方式（LAN/WAN/Internet）都能访问同一数据库。

## 二、为什么现代管理软件倾向 B/S

- **维护升级革命（瘦客户机）**：无论用户规模多大、多少分支机构，操作只针对服务器；异地只需联网即可维护升级，人力/时间/费用节省惊人。客户端只是浏览器，免维护。
- **成本降低、选择更多**：应用只装服务器，服务器操作系统可任选（含免费 Linux），桌面仍是 Windows 不受影响。
- **移动办公**：办公室内任意电脑、回家/出差只要有网就能办公；分公司经互联网/专线/电话网协同。
- **系统整合**：OA/HR/CRM/ERP 趋势是不断融合，统一 B/S 结构是当前与将来的最优选择。

> 注：Access 本身是桌面数据库。本技能用它做的系统多走"Access 前端 + SQL Server/链接表后端"的准 C/S 路线（后端分离见 `docs/troubleshooting.md` 与 `references/vcs-three-channels.md`）；是否上 B/S 取决于并发与部署需求，不是本技能的默认形态。

## 三、Access 的两种网络操作模式

1. **文件服务器模式（.accdb 文件夹共享）**
   - 数据处理全在客户机，文件服务器只传整个文件、不解析内容。
   - 优点：资源共享、简单、维护成本低。
   - 局限：① 网络传输冗余大（改一条记录也要传整个库文件），性能随用户数下降；② 加锁以整个文件为单位，一人打开他人不能写，多用户不便。
2. **客户机/服务器模式（Access + SQL Server）**
   - 数据处理可在两端进行；服务器按需挑选用锁、只传符合条件的数据，网络负载低、性能好。
   - 数据集中、易维护；服务器 OS 可跟踪多用户并发。
   - 代价：服务器硬件支出较大。

## 四、与本技能工作流的对应

- **阶段 0 选底座**：单用户/小团队先用 Access 本身；多用户并发把后端拆成 SQL Server 链接表（文件服务器模式的局限倒逼此决策）。
- **阶段 8 部署与运维**：后端库与主库分离成链接表便于备份与多人共享；并发写用后端库的行级锁而非 Access 文件锁；若需广域/移动访问再评估上 B/S 或 Web 前端。
- **真实案例对照**：一个完整财务系统（分析设计→建表→查询→窗体报表→VBA 模块）见 `references/开发财务管理系统.pdf`，它的章节顺序正好印证本工作流阶段 1→2→3→4→5→8。
